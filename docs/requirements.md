# Loom requirements

**Status:** Approved requirements. Implementation is in progress; see traceability for delivered cases.

This document defines the initial Loom scope. `LOOM-*` identifiers are stable. A change to a requirement's meaning requires review before implementation; identifiers must not be reused. Planned tests and their links to these requirements are in [requirements-traceability.md](requirements-traceability.md). The proposed technical contracts are in [loom-design.md](loom-design.md).

## Application and data

| ID | Requirement | Acceptance criterion |
| --- | --- | --- |
| LOOM-001 | Build Loom from this repository as `dist/loom.html`, using the existing Node and esbuild toolchain and a pinned Scittle release. | The artifact starts from `file://` with embedded CSS, JavaScript, and Scittle, executes a ClojureScript block without a network request, and includes the Scittle license attribution. No external runtime assets or Nix installation are required. Foglio and Timetable keep their existing build commands. |
| LOOM-002 | Represent knowledge as independent items with immutable, unique IDs, a title, Markdown body, tags, and creation and modification timestamps. | Renaming or reordering an item preserves its ID and incoming references. Duplicate titles are allowed; duplicate IDs are rejected. |
| LOOM-003 | Persist a versioned knowledge base automatically in browser-local storage and as strict EDN files with explicit import and export. | Committed items and workspace state reload after reopening the page; supported values round-trip; unsupported schema versions, malformed EDN, duplicate IDs, and invalid workspace references are rejected before replacing live data. Corrupt local data is ignored, and local-write failures are reported. Unapplied drafts are reported before replacement or leaving. |
| LOOM-004 | Provide a shared, vertically stacked workspace where multiple items can remain open and be closed or focused independently, without a mandatory hierarchy or graph view. | The most recently opened item is at the top; opening a linked or searched item retains existing cards and their scroll/edit context; closing one card leaves the others open. |
| LOOM-005 | Resolve item links by stable ID rather than title or display position. | Canonical `[[item:uuid]]` Markdown links and generated Hiccup links display the target's current title and open it in the workspace; the legacy `loom:` URL form remains supported, and a missing target produces a local diagnostic without title fallback. |
| LOOM-006 | Provide fast incremental search as a direct entry point to items. | Case-insensitive partial matches are grouped with title/tag matches before content-only matches, each item appears once, and selecting a result opens it without clearing the workspace; empty and no-result states are explained. |
| LOOM-007 | Maintain workspace exploration history. | Back and forward revisit prior open-card and active-card states; saved open-card order survives an EDN export/import. Deleted item IDs in old history do not crash navigation. |

## Authoring, references, and rendering

| ID | Requirement | Acceptance criterion |
| --- | --- | --- |
| LOOM-008 | Support whole-item transclusion by stable item ID. | Canonical `![[item:uuid]]` Markdown embeds the referenced item in display mode without a visible border or source label; embedded content exposes no source buttons, updates when that source changes, and is never stored as a generated copy in the parent body. The legacy Markdown-image form remains supported. |
| LOOM-009 | Support section transclusion and nested transclusion with cycle and depth protection. | `![[item:uuid#heading-slug]]` resolves heading targets deterministically; missing sections, direct or indirect cycles, and excessive nesting display bounded, local diagnostics while unrelated content renders. |
| LOOM-010 | Keep transcluded content read-only. | Transclusion never exposes Open source or Edit source controls and never opens, edits, saves, or discards source state implicitly; editing the parent never writes to the source. |
| LOOM-011 | Render ordinary Markdown from a maintained parser through safe DOM construction. | Common text formatting, headings, lists, quotes, links, and code examples render; raw HTML is inert, and unsafe links or unsupported media do not execute. |
| LOOM-012 | Distinguish executable ClojureScript snippets from ordinary Markdown code examples using documented fence markers. | Only fences tagged `clojurescript` (canonical) or `cljs loom` (legacy compatibility) are executable. A `clojure` fence is display-only and safely syntax-highlighted; `cljs` fences and inline code remain examples. Executable results appear at the fence's position. |
| LOOM-013 | Execute executable blocks automatically whenever their item is rendered in display mode. | Opening, applying an edit, importing an open item, and dependency-driven refreshes evaluate current `clojurescript` or legacy `cljs loom` source without a Run action. Source code is shown in item editing, results are shown in display mode, and transcluded executable fences remain inert. Imported executable content is therefore trusted content. |
| LOOM-014 | Expose a documented ClojureScript item and navigation API. | `loom/items`, `loom/item`, `loom/link`, and `loom/data` work with ordinary ClojureScript expressions, preserve item IDs, and return the documented value types. The `loom.core` namespace remains compatible. |
| LOOM-015 | Render snippet results according to value type. | Strings and scalar values become text, ordinary data has an EDN presentation, supported Hiccup becomes DOM, and collections of Hiccup nodes render in order. Generated links navigate in Loom. |
| LOOM-016 | Support a documented Hiccup subset of elements, attributes, nested children, collections, styles, and keys. | Supported structures render predictably; `style` maps apply only documented formatting/layout properties, `key` accepts string or finite-number metadata without becoming a DOM attribute, and unknown tags, malformed nodes, and unsupported values show a local error rather than being treated as HTML source. |
| LOOM-017 | Apply safe attribute, style, and URL rules to both Markdown and Hiccup rendering. | Event handlers, active content tags, unsafe URL schemes, unapproved attributes, unsupported CSS properties, and CSS values containing URLs or legacy executable expressions are rejected; no arbitrary snippet-returned string is assigned to `innerHTML`. |
| LOOM-018 | Isolate snippet errors. | A parse, evaluation, or rendering error appears at the failing snippet with an actionable message and does not prevent the rest of the item or workspace from rendering. |
| LOOM-019 | Track dependencies for active snippets and transclusions. | Changes to an item read by ID or to a subscribed item-list/tag index refresh affected output; unrelated content changes do not rerun unrelated snippets. Output is derived rather than persisted. |
| LOOM-020 | Define a bounded lifecycle for snippet evaluation. | Entering item editing exposes source without replacing the saved model; Apply reruns snippets from the saved edit; Cancel restores the saved display; card closure removes subscriptions; an evaluation error remains local and the next render retries it. |

## Editing, experience, and integration

| ID | Requirement | Acceptance criterion |
| --- | --- | --- |
| LOOM-021 | Reuse Foglio's actual structural editing operations for ClojureScript snippets, with necessary corrections and regression coverage. | Pairing, protected deletion, forward and backward slurp/barf, splice, wrap, and indentation work on nested forms and respect strings, escapes, line comments, and reader-prefixed forms including `#(...)`, `#{...}`, `#"..."`, quote, deref, and metadata. All four slurp/barf directions retain the cursor and support `()`, `[]`, and `{}`; barf retains intervening comments and whitespace. Forward slurp never consumes a closing delimiter and ascends to the enclosing form when the inner collection has no following expression. |
| LOOM-022 | Keep snippet editing scoped to its source fence and preserve navigation context. | Applying or cancelling a snippet edit preserves surrounding Markdown, item ID, open cards, focus, and scroll position. |
| LOOM-023 | Present a narrow sidebar, a spacious stacked-card workspace, and clear search, source, error, and editing states across desktop and narrow viewports. | The sidebar is limited to New Item, Setup access, and the Updated, Opened, Search, and Tag item-browser pages; item boundaries, focus, active state, and errors remain legible without a dashboard or unrequested panels. |
| LOOM-024 | Support keyboard access and meaningful feedback. | Search, open, close, back, forward, formatting actions, edit, save, import, and source navigation are keyboard operable with visible focus and programmatic labels/status. Bold and italic expose Ctrl/Cmd+B and Ctrl/Cmd+I shortcuts. |
| LOOM-025 | Treat imported EDN, Markdown, and attachment bundles as data, and make the executable-code trust boundary clear. | EDN import cannot evaluate reader forms; Markdown and Hiccup results cannot inject active DOM; file references resolve only from the local attachment store rather than author-provided URLs; imported bundles validate identities, names, MIME types, sizes, and base64 payloads before storage; executable snippets run automatically when their item is rendered, so documentation warns that imported SCI code has browser JavaScript interop and must be trusted. |
| LOOM-026 | Preserve existing Foglio and Timetable behavior when shared code is extracted. | Their full relevant test suites and standalone builds pass, including existing EDN and Paredit cases. |
| LOOM-027 | Keep technical documentation in English and synchronized with delivered behavior. | README launch, storage, execution, and authoring instructions match the implemented artifact; planned features are labelled as planned until delivered. |
| LOOM-028 | Keep Loom standalone within the existing SPA project without a new framework, folder requirement, widget language, or graph visualization. | Dependency and final-diff review show only justified additions; navigation remains item-based and no graph or mandatory folder UI appears. |
| LOOM-029 | Provide contextual insertion of stable-ID item links while editing Markdown. | Typing `[[` opens a cursor-adjacent picker that reuses sidebar search grouping, supports mouse and keyboard selection, dismisses with Escape, and inserts only the selected `[[item:uuid]]` reference without altering unrelated text or unsaved changes. |
| LOOM-030 | Provide a Markdown formatting toolbar in item editing. | Bold, italic, strikethrough, inline code, heading, bulleted list, blockquote, item-link, and executable-code controls operate on the current selection or cursor; each has an SVG icon, tooltip, and accessible label; the executable-code control inserts a `clojurescript` fence and preserves surrounding Markdown. |
| LOOM-031 | Provide a single edit control for executable snippets. | Each executable block shows one subtly translucent labelled SVG **Edit code** control in its upper-right corner, fully visible on hover and keyboard focus; display mode aligns the evaluated output with that control's top row, while editor mode hides the control and shows the source with Apply and Cancel actions. |
| LOOM-032 | Use icon-only controls to commit or discard executable snippet edits. | **Apply code** and **Cancel** are labelled SVG buttons in the snippet editor's upper-right corner with tooltips, accessible labels, and keyboard support; their existing commit and discard behavior remains unchanged. |
| LOOM-033 | Show ClojureScript syntax highlighting while editing executable snippets. | The editable source field uses a classic web-safe monospace stack with fixed 14 px text and 21 px line height, synchronized with a DOM-safe, non-interactive highlighting layer; comments, strings, literals, keywords, built-ins, and numbers are visually distinguished; ligatures are disabled and soft wrapping is supported; highlighting follows input and scroll without changing source text or bypassing the renderer's safe tokenization. |
| LOOM-034 | Protect structural boundaries during character deletion. | With a collapsed cursor immediately after a closing delimiter or before an opening delimiter, Backspace or Delete moves the cursor across the delimiter instead of removing it; the rule covers round, square, and curly brackets and double quotes, including delimiters at the start or end of the source, while existing whole-pair removal and text deletion remain available. |
| LOOM-035 | Align the ClojureScript editor caret with the highlighted source. | The native textarea caret is hidden and an accessible, non-interactive custom caret is measured from the corresponding highlighted text offset; it follows input and scroll, spans the configured line height, hides for non-collapsed selections and while unfocused, and reappears at the selection position when focus returns. |
| LOOM-036 | Suggest existing tags while editing an item. | Focusing or typing in the Tags field shows a context-anchored, accessible list of tags already used by the current item store; suggestions filter case-insensitively, exclude tags already entered and duplicate names, support mouse and keyboard selection, replace only the current tag token, and dismiss with Escape without altering the field. |
| LOOM-037 | Edit item titles in place in the card header. | Display mode presents the title as an accessible clickable control; activating it enters editing with the title field in the header at the same position, the item editor contains no duplicate title field, and Apply and Cancel preserve the existing update and draft semantics. |
| LOOM-038 | Provide a dedicated setup page in the left sidebar for knowledge-base and attachment file operations. | A Setup control toggles a sidebar page that owns Save EDN, Import EDN, Export files, and Import files; switching back restores the previous browser page, search query, and results, and the control exposes its expanded state while focus moves into or out of the page predictably. |
| LOOM-039 | Store item attachments as local blobs referenced by stable IDs. | Attaching a file from a note item stores it in IndexedDB under a UUID and inserts `[[file:uuid]]`; `![[file:uuid]]` renders through a local object URL with safe alt text, a missing attachment is a local diagnostic, and no external image URL is required. |
| LOOM-040 | Export and import all attachments independently of the EDN knowledge base. | Setup exports every stored attachment into one versioned JSON bundle with base64 bytes and validated metadata, and imports the same format by validating IDs, filenames, MIME types, byte counts, and duplicate IDs before merging; malformed bundles leave the attachment store unchanged, and imported files immediately resolve existing item references. |
| LOOM-041 | Complete saved file references from the Markdown editor. | Typing `[[file:` or `![[file:` opens a keyboard-accessible picker of public stored attachments; entries show the filename, MIME type, size, and a small image preview when available (otherwise a generic file icon), filter incrementally by filename, and insert only the stable file ID at the trigger position; empty and no-match states are explicit, private image-item attachments are excluded, and the picker never searches attachment bytes as item content. |
| LOOM-042 | Create dedicated image items by pasting a screenshot on the Loom page. | A page-level paste of image clipboard data creates one `:image` item per image without changing any open note or draft, stores the blob in IndexedDB, records its UUID as the image item's private attachment, titles the item `Screenshot: item:<item-uuid>`, opens the card at the top of the workspace, renders the image only inside that card or an explicit item transclusion, excludes the raw file reference from file completion and note Markdown, persists and reloads it with workspace state, and removes the private blob when the image item is deleted. Non-image clipboard files do not create image items. |
| LOOM-043 | Preview and transclude image items from `![[` completion. | With image items present, typing `![[` lists them with their image thumbnails and current `Screenshot: item:<uuid>` titles; searching filters the same item index, keyboard and mouse selection inserts only `![[item:<uuid>]]`, and the resulting transclusion displays the image through a local object URL inside a read-only embed without a source header, action buttons, or mutation of either item. |
| LOOM-044 | Close every open item from the workspace toolbar. | An icon-only SVG control with an accessible label and tooltip is disabled when no item is open and otherwise closes every card without deleting stored data; the transition is recorded in workspace history, focus moves to search, and unsaved edits require confirmation before being discarded. |
| LOOM-045 | Warn before deleting an item that is still referenced or transcluded. | Deletion scans other stored item bodies through the Markdown token stream for `[[item:uuid]]`, `![[item:uuid]]`, and supported legacy `loom:` link/image references while ignoring code and escaped literal text; if references exist, a modal lists each source item once and offers Open all and Cancel instead of deleting. Open all opens the sources while preserving other cards and the target; Cancel closes the modal and retains the target. With no references, Loom opens its own confirmation dialog with Delete and Cancel rather than a browser-native confirm; Cancel retains the target and Delete removes it. |
| LOOM-046 | Show an item's tags in presentation mode and make them navigate by tag. | A displayed item with tags shows them as accessible keyword buttons above its content; activating a tag opens the Tag browser page for that tag without opening or editing the source item. Untagged items show no empty list, editing replaces the buttons with the existing Tags field, and Apply or Cancel restores the current saved tags. |
| LOOM-047 | Suggest ClojureScript symbols and show their documentation while editing executable snippets. | Typing a symbol prefix in a focused snippet editor opens an accessible suggestion list for common ClojureScript core functions and macros plus the implemented Loom API; selecting an entry shows its signature and description, `Enter`/`Tab` or a mouse click inserts only the current symbol, arrow keys change selection, and `Escape` dismisses the list. `Ctrl/Cmd+Space` forces suggestions, while strings, comments, and non-empty selections suppress them. Existing Enter, Tab, and Paredit behavior is unchanged when the list is closed. |
| LOOM-048 | Expose creation time, modification time, referenced items, and transcluded items in item data. | Item summaries and full item reads include UTC `:created-at` and `:updated-at` strings plus derived `:referenced-items` and `:transcluded-items` vectors in first-reference order; relationships contain existing `{:id ... :title ...}` targets only, ignore code and malformed references, and are never persisted separately from the Markdown body. |
| LOOM-049 | Evaluate a complete s-expression from the snippet editor and show its output below the source. | `Ctrl/Cmd+Enter` at the end of a complete form evaluates only that form in the shared `loom.user` session without applying the editor draft; definitions define or redefine the named function for later evaluations. A value uses the normal safe result renderer, a definition reports the defined name, and evaluation errors remain in a labelled live bottom output area. A cursor inside an unfinished token is rejected locally. |
| LOOM-050 | Expose the hosting item to executable snippets. | `(loom/current-item-id)` returns the stable ID of the item whose block is executing, and `(loom/current-item)` returns its full item map; both return nil when no host context is supplied. The context is passed explicitly for automatic rendering and manual snippet evaluation, is never inferred from workspace selection or title, and the compatibility aliases are available under `loom.core`. |
| LOOM-051 | Provide a paginated, multi-page sidebar browser for recent updates, recently opened items, and search matches. | Updated lists stored items newest first by `:updated-at`, using the stable ID as a deterministic tie-breaker; Opened follows the current session's most-recent-first open order and keeps items after their cards close; Search reuses the shared title/tag/content ranking. Each page shows at most eight items with Previous/Next controls only when multiple pages exist, search pagination resets when the query changes, plain searches start with an explicit prompt and no results have an explicit empty state, and edits or deletions refresh all affected lists without changing workspace state or duplicating items. |
| LOOM-052 | Provide a sidebar page filtered by one tag and open it from an item tag. | The Tag page uses the selected tag's canonical keyword name for an exact case-sensitive match, lists every matching item once, newest first by `:updated-at` with the stable ID as tie-breaker, and paginates with the shared eight-item controls. Activating a tag on a displayed item opens and focuses this page with the tag shown; the page explains the unselected state, reports an empty result if the tag disappears, and refreshes after edits or deletions without changing open cards. |

## Scope and change control

The initial release has no plugin loader, collaboration service, graph visualization, mandatory folders, HTML authoring mode, or executable-code sandbox. Executable code is trusted and runs automatically whenever its item is displayed, including imported content opened in the workspace. A maintained Markdown parser is the only new runtime package. Browser-local storage is the automatic recovery format, while EDN files remain the portable interchange format. These boundaries do not relax the requirements above.

Each implementation feature must follow tests first, an observed expected failure, the smallest passing implementation, targeted and relevant regression runs, documentation and traceability updates, and approval before the next implementation step. No feature branch merges into `master` without approval.
